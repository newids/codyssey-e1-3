# "최소 스키마 예시(데이터 형태 참고; 키 이름/구조는 일관되게 유지):"

---

**"데이터를 주고받을 때 약속된 가장 기본적인 틀을 지켜달라"**

---

### 1. 용어 풀이

*   **최소 스키마 (Minimal Schema):**
    *   **스키마**는 데이터의 '설계도'나 '구조'를 의미합니다.
    *   **최소**라는 말은 복잡한 부가 정보는 빼고, **반드시 있어야 하는 핵심 항목**만 모아놓았다는 뜻입니다.
*   **데이터 형태 참고:**
    *   제공된 예시 데이터가 어떤 모양(예: JSON, 리스트 등)인지 잘 보고 그 형식을 따르라는 의미입니다.
*   **키(Key) 이름/구조는 일관되게 유지:**
    *   데이터의 이름(Key)을 마음대로 바꾸지 마세요. (예: `name`을 `user_name`으로 바꾸지 말 것)
    *   데이터가 계층 구조(중첩된 모양)라면 그 층수나 순서도 그대로 유지하라는 뜻입니다.

---

### 2. 쉬운 예시

만약 어떤 시스템에서 **학생 정보**를 아래와 같은 **'최소 스키마'**로 정의했다고 가정해 봅시다.

```json
{
  "id": 1,
  "name": "김철수"
}
```

이때 **"키 이름과 구조를 일관되게 유지하라"**는 말은 다음과 같은 실수를 하지 말라는 뜻입니다.

*   **잘못된 예 1 (키 이름 변경):** `"name"` 대신 `"student_name"`이라고 쓰면 안 됨.
*   **잘못된 예 2 (구조 변경):** 갑자기 `"id"`를 다른 괄호 안에 넣거나 순서를 엉망으로 만들면 안 됨.
*   **잘못된 예 3 (데이터 타입 변경):** 숫자가 들어갈 `"id"` 자리에 갑자기 문자열을 넣으면 안 됨.

---

### 3. 왜 이렇게 해야 하나요?

컴퓨터나 프로그램끼리 데이터를 주고받을 때는 **정해진 규칙**이 매우 중요합니다. 
만약 한쪽에서 `id`라고 보내기로 했는데 다른 쪽에서 `번호`라고 이름을 바꿔버리면, 받는 쪽에서는 "id가 어디 갔지?"라며 데이터를 찾지 못하고 오류가 발생하게 됩니다.
